---

## 问题描述

用户点击登录按钮后,浏览器尝试访问 `http://10.242.94.9:8080/auth/login?return_url=%2F`,但无法访问该地址。

### 根本原因

1. **前端硬编码错误端口**: `LoginButton.js:58` 使用了错误的默认端口8080,而后端服务实际运行在8000端口
2. **Nginx配置问题**: 旧的nginx配置(`nginx.conf`)没有代理 `/auth/` 路径

---

## 解决方案

### 1. 修复OAuth回调地址 (已完成 ✅)

**文件**: `.env`

**修改前**:
```env
IDENTITY_HUB_REDIRECT_URI=http://10.242.94.9:8080/auth/callback
```

**修改后**:
```env
IDENTITY_HUB_REDIRECT_URI=http://10.242.94.9/auth/callback
```

**原理**: OAuth回调地址必须与用户实际访问的前端地址一致(80端口),否则Identity Hub会拒绝重定向。

**部署步骤**:
```bash
# 1. 修改.env文件(已完成)

# 2. 重新创建后端容器以加载新环境变量
docker-compose stop app
docker-compose rm -f app
docker-compose up -d app
```

### 2. 修复前端登录URL (已完成 ✅)

**文件**: `frontend/src/components/LoginButton.js`

**修改前**:
```javascript
const backendUrl = process.env.REACT_APP_BACKEND_URL || 'http://10.242.94.9:8080';
window.location.href = `${backendUrl}/auth/login?return_url=${returnUrl}`;
```

**修改后**:
```javascript
// 使用相对路径,让nginx代理到后端
window.location.href = `/auth/login?return_url=${returnUrl}`;
```

**原理**: 使用相对路径 `/auth/login`,由nginx自动代理到后端 `http://app:8000/auth/login`。

### 2. 验证Nginx配置 (已确认 ✅)

**文件**: `docker/nginx/nginx.frontend.conf` (实际使用的配置)

**关键配置** (52-60行):
```nginx
# OAuth认证端点反向代理
location /auth/ {
    proxy_pass http://app:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    # 传递Cookie用于session管理
    proxy_set_header Cookie $http_cookie;
}
```

**说明**:
- 该配置文件在Phase 4时已正确配置
- 将 `/auth/*` 请求代理到后端容器 `app:8000`
- 正确处理Cookie传递(session管理所需)

## 技术细节

### Docker网络架构
```
用户浏览器 (http://10.242.94.9)
    ↓
docker_frontend_1:80 (Nginx)
    ├── / → 静态文件 (/usr/share/nginx/html)
    ├── /api/ → proxy_pass http://app:8000/api/
    └── /auth/ → proxy_pass http://app:8000/auth/
                      ↓
            docker_app_1:8000 (FastAPI后端)
                └── auth_routes.py
                    ├── GET /auth/login → 生成OAuth URL并重定向
                    ├── GET /auth/callback → 处理OAuth回调
                    ├── POST /auth/logout → 登出
                    └── GET /auth/status → 认证状态
```

### 认证流程
1. 用户点击"登录"按钮
2. 前端跳转: `window.location.href = "/auth/login?return_url=/"`
3. Nginx代理: `/auth/login` → `http://app:8000/auth/login`
4. 后端生成OAuth URL并返回307重定向到Identity Hub
5. 用户在Identity Hub完成登录
6. Identity Hub回调: `/auth/callback?code=xxx&state=xxx`
7. 后端交换授权码获取token并创建session
8. 重定向回前端 `return_url`
