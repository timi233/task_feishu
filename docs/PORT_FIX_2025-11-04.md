# 端口配置修复记录

**日期**: 2025-11-04
**问题**: OAuth回调地址端口错误(8081→8080)

## 问题描述

在文件归类整理后启动开发环境，发现OAuth登录回调地址仍然指向8081端口，但实际后端运行在8080端口，导致登录授权后无法正确回调。

## 根本原因

项目配置中存在多处硬编码的8081端口：
1. **前端配置**: `frontend/package.json` - proxy代理配置
2. **前端代码**: `frontend/src/components/LoginButton.js` - 登录跳转URL
3. **后端配置**: `.env` - OAuth回调地址

这些配置没有统一，导致前后端端口不一致。

## 修复方案

### 1. 前端Proxy配置修复 ✅

**文件**: `frontend/package.json`

```diff
- "proxy": "http://10.242.94.9:8081"
+ "proxy": "http://10.242.94.9:8080"
```

### 2. 前端登录URL修复 ✅

**文件**: `frontend/src/components/LoginButton.js`

```diff
- const backendUrl = process.env.REACT_APP_BACKEND_URL || 'http://10.242.94.9:8081';
+ const backendUrl = process.env.REACT_APP_BACKEND_URL || 'http://10.242.94.9:8080';
```

### 3. OAuth回调地址修复 ✅

**文件**: `.env`

```diff
- IDENTITY_HUB_REDIRECT_URI=http://10.242.94.9:8081/auth/callback
+ IDENTITY_HUB_REDIRECT_URI=http://10.242.94.9:8080/auth/callback
```

### 4. 服务重启 ✅

修改配置后需要重启相关服务：

```bash
# 1. 停止派工系统后端
pkill -f "uvicorn.*main:app.*8080"

# 2. 重启后端服务（新配置生效）
cd /home/jian/code/Task_feishu/backend
nohup uvicorn main:app --host 0.0.0.0 --port 8080 > /tmp/dispatch-backend.log 2>&1 &

# 3. 前端会自动热重载（检测到package.json变化）
# 如需手动重启：
# pkill -f "react-scripts start"
# cd frontend && npm start
```

## 技术细节

### 为什么需要修改三处？

1. **frontend/package.json (proxy)**
   - React开发服务器的proxy配置
   - 将前端API请求代理到后端
   - 影响：`/api/*`, `/auth/*` 等相对路径请求

2. **LoginButton.js (backendUrl)**
   - 登录跳转使用 `window.location.href`
   - 这种跳转不会被proxy拦截
   - 必须使用完整URL，所以需要明确指定后端地址

3. **.env (IDENTITY_HUB_REDIRECT_URI)**
   - 后端OAuth配置
   - 告诉Identity Hub授权后回调的地址
   - 必须与实际运行端口一致

### Identity Hub应用配置

Identity Hub中注册的OAuth应用配置应包含：

```
应用ID: task_feishu_dispatch_system
回调地址白名单:
  - http://10.242.94.9:8080/auth/callback
  - http://localhost:8080/auth/callback
```

**注意**: Identity Hub的回调地址白名单需要在Identity Hub后台手动配置，确保包含8080端口的回调地址。
